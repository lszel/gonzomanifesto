1. ڈویلپر کوڈ کا حصہ ہے: غیر جانب دار ترقی وجود نہیں رکھتی۔ سافٹ ویئر پروگرامر کی ذہنی حالت، بلڈ پریشر اور غصے کا بائنری نقش ہے۔

2. افراتفری مقدس ہے: حد سے زیادہ واضح الگورتھم مشکوک ہے۔ حقیقی گونزو کوڈ جنگل کی طرح ہے: خطرناک، تاریک، اور جالوں کی جگہ صرف خالق جانتا ہے۔

3. پروڈکشن سرور پر جانچ: Unit test بزدلوں اور افسر شاہی کا کھیل ہے۔ گونزو پروگرامر صارفین کی چیخوں کے درمیان production میں debugging کرتا ہے۔

4. دستاویزات افسانہ ہیں: Comments وضاحت نہیں بلکہ اندرونی مکالمے، سیاسی منشور یا مدد کی پکار ہیں۔ جو کوڈ نہیں سمجھتا وہ اسے استعمال کرنے کے قابل نہیں۔

5. Pointer حاکم ہے: ایسی زبان استعمال کرو جو تمہیں محدود نہ کرے! براہ راست memory management آزادی کی ضمانت ہے۔ Safe type زنجیر ہے۔ Memory Leak تمہاری وہ چیخ ہے جسے کوئی نہیں سنتا۔

6. کیفین پر مبنی معماری: کوڈ کا معیار محرکات کی مقدار کے راست اور نیند کے گھنٹوں کے الٹ تناسب میں ہے۔

7. Error message بطور فن: اسے مدد نہیں بلکہ صدمہ دینا چاہیے۔ ہر Runtime Error پر صارف کو مشین کی تحقیر محسوس ہونی چاہیے۔

8. کبھی صفائی نہ کرو (Refactor): وجد کی حالت میں لکھا ہوا مقدس ہے۔ اسے “خوب صورت” بنانے سے سافٹ ویئر کی روح مر جاتی ہے۔

9. آخری تاریخ صرف تجویز ہے: گونزو پروگرامر تحریک اور خوف کی لہروں پر سوار ہوتا ہے۔ ڈویلپر کے گرنے پر کوڈ مکمل ہوتا ہے۔

10. سافٹ ویئر ناقابل پیش گوئی ہونا چاہیے: اچھے گونزو پروگرام میں اتفاق ہوتا ہے۔ اگر ہمیشہ ایک ہی ہو تو وہ صنعتی مصنوع ہے، فن نہیں۔

11. ذمہ داری؟ خارج: لائسنس کہے: “اگر چل گیا تو یہ تمہارا مسئلہ ہے۔” ڈویلپر خدا نہیں، مشین کی تباہی کا گواہ ہے۔

12. خروج کی حکمت عملی: منصوبہ گرے تو وضاحت نہ دو۔ Git history مٹاؤ، hard drive جلاؤ اور میکسیکو میں mobile signal کے بغیر جگہ تلاش کرو۔
