1. توسعه‌دهنده بخشی از کد است: توسعهٔ عینی وجود ندارد. نرم‌افزار ابزار نیست، بلکه نقش دودویی وضعیت ذهنی، فشار خون و خشم برنامه‌نویس در همان روز است.

2. آشوب مقدس است: اگر الگوریتمی بیش از حد شفاف باشد، مشکوک است. کد واقعی گونزو مانند جنگل است: خطرناک، تاریک، و فقط سازنده‌اش می‌داند تله‌ها کجا هستند.

3. آزمایش روی سرور تولید: Unit test ورزش ترسوها و دیوان‌سالارهاست. برنامه‌نویس واقعی گونزو در محیط تولید و میان فریادهای کاربران debugging می‌کند.

4. مستندات داستانی است: توضیحات کنار کد، توضیح واقعی نیستند؛ بلکه تک‌گویی‌های درونی، بیانیه‌های سیاسی یا فریادهای کمک‌اند. کسی که کد را نمی‌فهمد، شایستهٔ استفاده از آن نیست.

5. اشاره‌گر (pointer) فرمانرواست: از زبان برنامه‌نویسی‌ای استفاده کن که محدودت نکند! مدیریت مستقیم حافظه تضمین آزادی توست. استفاده از نوع‌های امن فقط یک زنجیر است. از نشانی‌های حافظه چنان استفاده کن که گویی فردایی وجود ندارد. Memory Leak فریاد توست که هیچ‌کس نمی‌شنود.

6. معماری مبتنی بر کافئین: کیفیت کد با مقدار محرک‌های مصرف‌شده نسبت مستقیم و با تعداد ساعت‌های خواب نسبت معکوس دارد.

7. پیام خطا به‌عنوان هنر: پیام خطا نباید کمک کند، بلکه باید شوکه کند. کاربر باید در هر Runtime Error تحقیر ماشین و سازنده‌اش را احساس کند.

8. هرگز پاک‌سازی نکن (Refactor): آنچه یک بار در حالت خلسه نوشته‌ای مقدس است. اگر برای «زیباتر» کردن به آن دست بزنی، روح نرم‌افزار را می‌کشی.

9. مهلت فقط یک پیشنهاد است: برنامه‌نویس گونزو با ساعت کار نمی‌کند، بلکه بر موج‌های الهام و هراس سوار می‌شود. کد زمانی تمام می‌شود که توسعه‌دهنده از پا بیفتد.

10. نرم‌افزار باید پیش‌بینی‌ناپذیر باشد: یک برنامهٔ خوب گونزو همیشه کمی تصادفی بودن دارد. اگر با هر بار فشار دادن دکمه همان اتفاق بیفتد، آن یک محصول صنعتی کسل‌کننده است، نه هنر.

11. مسئولیت؟ منتفی است: قرارداد مجوز باید تنها یک بند داشته باشد: «اگر اجرا شد، مشکل خودت است.» توسعه‌دهنده خدا نیست، فقط شاهد نابودی ماشین است.

12. راهبرد خروج: وقتی پروژه فروپاشید، توضیح نده. تاریخچهٔ Git را حذف کن، دیسک سخت را بسوزان و جایی در مکزیک پیدا کن که آنتن موبایل نداشته باشد.
