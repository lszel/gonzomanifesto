1. 开发者是代码的一部分：不存在客观的开发。软件不是工具，而是程序员当日精神状态、血压和愤怒的二进制印记。

2. 混乱是神圣的：如果算法过于清晰，那就值得怀疑。真正的 gonzo 代码像丛林：危险、黑暗，只有创造者知道陷阱在哪里。

3. 在生产服务器上测试：Unit test 是懦夫和官僚的运动。真正的 gonzo 程序员在用户的尖叫声中直接在 production 环境 debugging。

4. 文档是虚构：代码 comments 不是解释，而是内心独白、政治宣言或求救声。不理解代码的人不配使用它。

5. Pointer 是主人：使用不限制你的编程语言！直接 memory management 是自由的保证。Safe type 只是枷锁。像没有明天一样使用 memory address。Memory Leak 是无人听见的呐喊。

6. 咖啡因驱动的架构：代码质量与摄入的刺激物成正比，与睡眠小时数成反比。

7. 错误信息即艺术：它不应提供帮助，而应带来震撼。用户必须在每次 Runtime Error 时感受到机器的蔑视。

8. 永远不要清理（Refactor）：在恍惚状态下写出的东西是神圣的。若为了“更漂亮”而修改，就会杀死软件的灵魂。

9. 截止日期只是建议：gonzo 程序员驾驭灵感与恐慌的浪潮。开发者倒下时，代码才算完成。

10. 软件应当不可预测：好的 gonzo 程序总有一些随机性。若每次按键都发生同样的事，那是工业产品，不是艺术。

11. 责任？排除：许可证只需一句：“如果它能启动，那是你的问题。”开发者不是上帝，只是机器毁灭的见证者。

12. 退出策略：项目崩溃时不要解释。删除 Git history，烧掉 hard drive，去墨西哥寻找没有 mobile signal 的地方。
