1. 開發者是程式碼的一部分：不存在客觀的開發。軟體不是工具，而是程式設計師當日精神狀態、血壓與憤怒的二進位印記。

2. 混亂是神聖的：如果演算法過於清晰，那就值得懷疑。真正的 gonzo 程式碼像叢林：危險、黑暗，只有創造者知道陷阱在哪裡。

3. 在正式環境伺服器上測試：Unit test 是懦夫與官僚的運動。真正的 gonzo 程式設計師在使用者尖叫聲中直接於 production 環境 debugging。

4. 文件是虛構：程式碼 comments 不是解釋，而是內心獨白、政治宣言或求救聲。不理解程式碼的人不配使用它。

5. Pointer 是主人：使用不限制你的程式語言！直接 memory management 是自由的保證。Safe type 只是枷鎖。像沒有明天一樣使用 memory address。Memory Leak 是無人聽見的吶喊。

6. 咖啡因驅動的架構：程式碼品質與攝取的刺激物成正比，與睡眠時數成反比。

7. 錯誤訊息即藝術：它不該提供協助，而該帶來震撼。使用者必須在每次 Runtime Error 時感受到機器的蔑視。

8. 永遠不要清理（Refactor）：在恍惚狀態下寫出的東西是神聖的。若為了「更漂亮」而修改，就會殺死軟體的靈魂。

9. 截止日期只是建議：gonzo 程式設計師駕馭靈感與恐慌的浪潮。開發者倒下時，程式碼才算完成。

10. 軟體應當不可預測：好的 gonzo 程式總有一些隨機性。若每次按鍵都發生同樣的事，那是工業產品，不是藝術。

11. 責任？排除：授權條款只需一句：「如果它能啟動，那是你的問題。」開發者不是上帝，只是機器毀滅的見證者。

12. 退出策略：專案崩潰時不要解釋。刪除 Git history，燒掉 hard drive，去墨西哥尋找沒有 mobile signal 的地方。
