1. Розробник є частиною коду: Об’єктивної розробки не існує. Програмне забезпечення — двійковий відбиток душевного стану, тиску та гніву програміста.

2. Хаос священний: Надто прозорий алгоритм підозрілий. Справжній гонзо-код схожий на джунглі: небезпечний, темний, і лише творець знає, де пастки.

3. Тестування на виробничому сервері: Unit-тести — спорт боягузів і бюрократів. Гонзо-програміст налагоджує у production серед криків користувачів.

4. Документація — вигадка: Коментарі — внутрішні монологи, політичні маніфести або крики про допомогу. Хто не розуміє код, не гідний ним користуватися.

5. Вказівник (pointer) — володар: Використовуй мову без обмежень! Пряме керування пам’яттю гарантує свободу. Безпечні типи — кайдани. Memory Leak — твій крик, якого ніхто не чує.

6. Кофеїнова архітектура: Якість коду прямо пропорційна стимуляторам і обернено пропорційна годинам сну.

7. Повідомлення про помилку як мистецтво: Воно має не допомагати, а шокувати. Користувач повинен відчувати зневагу машини при кожному Runtime Error.

8. Ніколи не очищуй (Refactor): Написане у трансі святе. Зробивши його “красивішим”, ти вб’єш душу програми.

9. Термін — лише пропозиція: Гонзо-програміст їде на хвилях натхнення й паніки. Код готовий, коли розробник падає.

10. Програма має бути непередбачуваною: У хорошому гонзо-коді є випадковість. Якщо завжди відбувається те саме, це промисловий продукт, не мистецтво.

11. Відповідальність? Виключена: Ліцензія каже: “Якщо запускається, це твоя проблема.” Розробник не Бог, а свідок загибелі машини.

12. Стратегія виходу: Коли проєкт впаде, не виправдовуйся. Видали історію Git, спали диск і знайди в Мексиці місце без мобільного сигналу.
