1. 개발자는 코드의 일부다: 객관적인 개발은 없다. 소프트웨어는 도구가 아니라, 그날 프로그래머의 정신 상태와 혈압과 분노가 남긴 이진 흔적이다.

2. 혼돈은 신성하다: 알고리즘이 지나치게 명확하다면 의심스럽다. 진정한 곤조 코드는 정글과 같다. 위험하고 어두우며, 함정이 어디에 있는지는 오직 창조자만 안다.

3. 운영 서버에서 테스트한다: Unit test는 겁쟁이와 관료들의 스포츠다. 진정한 곤조 프로그래머는 사용자들의 비명 속에서 운영 환경을 직접 디버깅한다.

4. 문서는 허구다: 코드에 붙은 주석은 설명이 아니라 내면의 독백, 정치적 선언문 또는 구조 요청이다. 코드를 이해하지 못하는 사람은 그것을 사용할 자격이 없다.

5. 포인터(pointer)가 주인이다: 당신을 제한하지 않는 프로그래밍 언어를 사용하라! 직접적인 메모리 관리는 자유의 보증이다. 안전한 타입을 사용하는 것은 족쇄일 뿐이다. 내일이 없는 것처럼 메모리 주소를 사용하라. Memory Leak는 아무도 듣지 못하는 당신의 비명이다.

6. 카페인 기반 아키텍처: 코드의 품질은 섭취한 자극제의 양에 정비례하고, 수면에 쓴 시간에 반비례한다.

7. 오류 메시지는 예술이다: 오류 메시지는 도움을 주는 것이 아니라 충격을 주어야 한다. 사용자는 모든 Runtime Error 순간에 기계와 그 창조자의 경멸을 느껴야 한다.

8. 절대 정리하지 마라(Refactor): 황홀경 속에서 한 번 작성한 것은 신성하다. 그것을 “더 예쁘게” 만들려고 손대면 소프트웨어의 영혼을 죽이게 된다.

9. 마감일은 제안일 뿐이다: 곤조 프로그래머는 시계에 맞춰 일하지 않고 영감과 공황의 파도를 탄다. 개발자가 무너질 때 코드가 완성된다.

10. 소프트웨어는 예측 불가능해야 한다: 좋은 곤조 프로그램에는 언제나 약간의 무작위성이 있다. 버튼을 누를 때마다 같은 일이 일어난다면 그것은 지루한 산업 제품이지 예술이 아니다.

11. 책임? 제외한다: 라이선스 계약은 단 한 조항으로 이루어져야 한다. “실행된다면, 그건 네 문제다.” 개발자는 신이 아니라 기계의 파멸을 지켜보는 증인일 뿐이다.

12. 출구 전략: 프로젝트가 무너지면 해명하지 마라. Git 기록을 삭제하고, 하드 드라이브를 불태우고, 휴대전화 신호가 없는 멕시코의 장소를 찾아라.
