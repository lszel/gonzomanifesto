1. นักพัฒนาเป็นส่วนหนึ่งของโค้ด: ไม่มีการพัฒนาที่เป็นกลาง ซอฟต์แวร์ไม่ใช่เครื่องมือ แต่เป็นรอยประทับแบบไบนารีของสภาพจิตใจ ความดันโลหิต และความโกรธของโปรแกรมเมอร์ในวันนั้น

2. ความโกลาหลเป็นสิ่งศักดิ์สิทธิ์: หากอัลกอริทึมโปร่งใสเกินไปย่อมน่าสงสัย โค้ดกอนโซที่แท้จริงเหมือนป่า: อันตราย มืด และมีเพียงผู้สร้างที่รู้ว่ากับดักอยู่ที่ไหน

3. ทดสอบบนเซิร์ฟเวอร์ production: Unit test เป็นกีฬาของคนขี้ขลาดและข้าราชการ โปรแกรมเมอร์กอนโซตัวจริงทำ debugging ใน production ท่ามกลางเสียงกรีดร้องของผู้ใช้

4. เอกสารคือเรื่องแต่ง: comments ในโค้ดไม่ใช่คำอธิบาย แต่เป็นบทพูดภายใน แถลงการณ์ทางการเมือง หรือเสียงร้องขอความช่วยเหลือ ผู้ที่ไม่เข้าใจโค้ดไม่คู่ควรกับการใช้งาน

5. Pointer คือเจ้านาย: ใช้ภาษาโปรแกรมที่ไม่จำกัดคุณ! การจัดการ memory โดยตรงคือหลักประกันแห่งเสรีภาพ Safe type เป็นเพียงโซ่ตรวน ใช้ memory address ราวกับไม่มีวันพรุ่งนี้ Memory Leak คือเสียงกรีดร้องของคุณที่ไม่มีใครได้ยิน

6. สถาปัตยกรรมที่ขับเคลื่อนด้วยคาเฟอีน: คุณภาพโค้ดแปรผันตรงกับปริมาณสารกระตุ้น และแปรผกผันกับจำนวนชั่วโมงนอน

7. ข้อความผิดพลาดในฐานะศิลปะ: มันไม่ควรช่วย แต่ควรทำให้ตกใจ ผู้ใช้ต้องสัมผัสการดูหมิ่นของเครื่องจักรในทุก Runtime Error

8. อย่าทำความสะอาดเด็ดขาด (Refactor): สิ่งที่เขียนในภาวะเคลิบเคลิ้มย่อมศักดิ์สิทธิ์ หากแตะเพื่อให้ “สวยขึ้น” คุณจะฆ่าวิญญาณของซอฟต์แวร์

9. เส้นตายเป็นเพียงข้อเสนอ: โปรแกรมเมอร์กอนโซขี่คลื่นแห่งแรงบันดาลใจและความตื่นตระหนก โค้ดเสร็จเมื่อผู้พัฒนาล้มลง

10. ซอฟต์แวร์ต้องคาดเดาไม่ได้: โปรแกรมกอนโซที่ดีมีความสุ่มอยู่เสมอ หากกดปุ่มแล้วเกิดสิ่งเดิมทุกครั้ง นั่นคือสินค้าอุตสาหกรรม ไม่ใช่ศิลปะ

11. ความรับผิดชอบ? ตัดออก: ใบอนุญาตควรบอกเพียงว่า “ถ้ามันเปิดติด นั่นคือปัญหาของคุณ” นักพัฒนาไม่ใช่พระเจ้า เป็นเพียงพยานต่อการพังทลายของเครื่องจักร

12. กลยุทธ์ทางออก: เมื่อโครงการพัง อย่าอธิบาย ลบ Git history เผา hard drive และหาสถานที่ในเม็กซิโกที่ไม่มี mobile signal
