1. 開発者はコードの一部である：客観的な開発など存在しない。ソフトウェアは道具ではなく、その日のプログラマーの精神状態、血圧、怒りが刻まれた二進数の痕跡である。

2. 混沌は神聖である：アルゴリズムがあまりに明快なら、それは怪しい。本物のゴンゾー・コードはジャングルのようなものだ。危険で、暗く、罠の場所を知るのは作者だけである。

3. 本番サーバーでテストする：Unit test は臆病者と官僚のスポーツである。本物のゴンゾー・プログラマーは、ユーザーの悲鳴の中、本番環境でデバッグする。

4. ドキュメントは虚構である：コードに付けられたコメントは説明ではない。内なる独白、政治的マニフェスト、あるいは助けを求める叫びである。コードを理解できない者に、それを使う資格はない。

5. ポインター（pointer）こそ支配者である：制限されないプログラミング言語を使え！直接的なメモリ管理は自由の保証である。安全な型の使用はただの足かせだ。明日などないかのようにメモリアドレスを使え。Memory Leak は、誰にも聞かれないあなたの叫びである。

6. カフェイン駆動アーキテクチャ：コードの品質は、摂取した刺激物の量に正比例し、睡眠時間に反比例する。

7. エラーメッセージを芸術にする：エラーメッセージは助けるのではなく、衝撃を与えなければならない。ユーザーは Runtime Error のたびに、機械と作者からの軽蔑を感じるべきである。

8. 決して片づけるな（Refactor）：トランス状態で一度書いたものは神聖である。「きれい」にしようと手を入れれば、ソフトウェアの魂を殺すことになる。

9. 締め切りは単なる提案である：ゴンゾー・プログラマーは時計に従って働かない。ひらめきとパニックの波に乗る。コードが完成するのは、開発者が倒れたときである。

10. ソフトウェアは予測不能であるべきだ：優れたゴンゾー・プログラムには、常に少しのランダム性がある。ボタンを押すたびに同じことが起きるなら、それは退屈な工業製品であって、芸術ではない。

11. 責任？ 排除する：ライセンス契約は一項だけでよい。「起動したなら、それはあなたの問題だ。」開発者は神ではない。ただ機械の破滅を目撃する者である。

12. 撤退戦略：プロジェクトが崩壊したら、弁明するな。Git の履歴を削除し、ハードディスクを焼き、携帯電話の電波が届かないメキシコの場所を探せ。
