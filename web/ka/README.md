1. დეველოპერი კოდის ნაწილია: ობიექტური განვითარება არ არსებობს. პროგრამული უზრუნველყოფა ინსტრუმენტი კი არა, არამედ პროგრამისტის იმ დღის სულიერი მდგომარეობის, არტერიული წნევისა და გაბრაზების ბინარული ანაბეჭდია.

2. ქაოსი წმინდაა: თუ ალგორითმი ზედმეტად გამჭვირვალეა, ეს საეჭვოა. ნამდვილი გონზო კოდი ჯუნგლებს ჰგავს: საშიშია, ბნელი და მხოლოდ მისმა შემქმნელმა იცის, სად არის ხაფანგები.

3. ტესტირება საწარმოო სერვერზე: Unit test-ები მშიშრებისა და ბიუროკრატების სპორტია. ნამდვილი გონზო პროგრამისტი შეცდომებს უშუალოდ საწარმოო გარემოში, მომხმარებლების ყვირილის ფონზე ასწორებს.

4. დოკუმენტაცია გამონაგონია: კოდზე დართული კომენტარები ახსნა კი არა, შინაგანი მონოლოგები, პოლიტიკური მანიფესტები ან დახმარების ძახილია. ვინც კოდს ვერ იგებს, მისი გამოყენების ღირსი არ არის.

5. მაჩვენებელი (pointer) ბატონია: გამოიყენე პროგრამირების ენა, რომელშიც არ გზღუდავენ! მეხსიერების უშუალო მართვა შენი თავისუფლების გარანტიაა. უსაფრთხო ტიპების გამოყენება მხოლოდ ბორკილია. გამოიყენე მეხსიერების მისამართები ისე, თითქოს ხვალინდელი დღე არ არსებობდეს. Memory Leak შენი ყვირილია, რომელიც არავის ესმის.

6. კოფეინზე დაფუძნებული არქიტექტურა: კოდის ხარისხი პირდაპირ პროპორციულია მიღებული სტიმულატორების რაოდენობისა და უკუპროპორციულია ძილში გატარებული საათების რაოდენობისა.

7. შეცდომის შეტყობინება, როგორც ხელოვნება: შეცდომის შეტყობინება არ უნდა გეხმარებოდეს, არამედ უნდა გაოგნებდეს. მომხმარებელმა ყოველი Runtime Error-ის დროს მანქანისა და მისი შემქმნელის ზიზღი უნდა იგრძნოს.

8. არასოდეს გაწმინდო (Refactor): ის, რაც ერთხელ ტრანსის მდგომარეობაში დაწერე, წმინდაა. თუ მას „გასალამაზებლად“ შეეხები, პროგრამული უზრუნველყოფის სულს მოკლავ.

9. ვადა მხოლოდ წინადადებაა: გონზო პროგრამისტი საათის მიხედვით არ მუშაობს, ის შთაგონებისა და პანიკის ტალღებზე მიექანება. კოდი მაშინ არის მზად, როცა დეველოპერი ჩამოიშლება.

10. პროგრამული უზრუნველყოფა არაპროგნოზირებადი უნდა იყოს: კარგ გონზო პროგრამაში ყოველთვის არის ცოტა შემთხვევითობა. თუ ღილაკის ყოველი დაჭერისას ერთი და იგივე ხდება, ეს მოსაწყენი სამრეწველო პროდუქტია და არა ხელოვნება.

11. პასუხისმგებლობა? გამორიცხულია: სალიცენზიო შეთანხმება ერთი პუნქტისგან უნდა შედგებოდეს: „თუ გაეშვა, ეს შენი პრობლემაა.“ დეველოპერი ღმერთი არ არის, მხოლოდ მანქანის დაღუპვის მოწმეა.

12. გასვლის სტრატეგია: როდესაც პროექტი ჩაიშლება, თავს ნუ იმართლებ. წაშალე Git-ის ისტორია, დაწვი მყარი დისკი და მექსიკაში იპოვე ადგილი, სადაც მობილური სიგნალი არ არის.
