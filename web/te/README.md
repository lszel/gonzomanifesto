1. డెవలపర్ కోడ్‌లో భాగం: నిష్పాక్షిక అభివృద్ధి లేదు. సాఫ్ట్‌వేర్ ఒక సాధనం కాదు; ఆ రోజు ప్రోగ్రామర్ మానసిక స్థితి, రక్తపోటు, కోపం యొక్క బైనరీ ముద్ర.

2. అస్తవ్యస్తత పవిత్రం: అల్గోరిథమ్ అతిగా స్పష్టంగా ఉంటే అది అనుమానాస్పదం. నిజమైన గోంజో కోడ్ అడవిలాంటిది: ప్రమాదకరం, చీకటి, ఉచ్చులు ఎక్కడున్నాయో సృష్టికర్తకే తెలుసు.

3. ప్రొడక్షన్ సర్వర్‌పై పరీక్ష: Unit test పిరికివాళ్లూ అధికారులూ ఆడే ఆట. నిజమైన గోంజో ప్రోగ్రామర్ వినియోగదారుల అరుపుల మధ్య production‌లో debugging చేస్తాడు.

4. డాక్యుమెంటేషన్ కల్పితం: కోడ్ comments వివరణలు కావు; అంతర్గత ఏకపాత్రాభినయాలు, రాజకీయ ప్రకటనలు లేదా సహాయం కోసం అరుపులు. కోడ్ అర్థం కానివాడు దాన్ని ఉపయోగించడానికి అర్హుడు కాదు.

5. Pointer అధిపతి: మిమ్మల్ని పరిమితం చేయని ప్రోగ్రామింగ్ భాషను వాడండి! ప్రత్యక్ష memory నిర్వహణ మీ స్వేచ్ఛకు హామీ. Safe type ఒక సంకెళ్లు మాత్రమే. రేపు లేదన్నట్టు memory address‌లను వాడండి. Memory Leak ఎవరూ వినని మీ అరుపు.

6. కెఫీన్ ఆధారిత నిర్మాణం: కోడ్ నాణ్యత తీసుకున్న ఉత్తేజకాల పరిమాణానికి ప్రత్యక్ష నిష్పత్తిలో, నిద్ర గంటలకు వ్యతిరేక నిష్పత్తిలో ఉంటుంది.

7. దోష సందేశం కళగా: అది సహాయం చేయకుండా దిగ్భ్రాంతి కలిగించాలి. ప్రతి Runtime Error వద్ద యంత్రం యొక్క తృణీకారాన్ని వినియోగదారు అనుభవించాలి.

8. ఎప్పుడూ శుభ్రం చేయవద్దు (Refactor): మైమరపు స్థితిలో రాసింది పవిత్రం. దాన్ని “అందంగా” చేయడానికి తాకితే సాఫ్ట్‌వేర్ ఆత్మను చంపుతారు.

9. గడువు ఒక సూచన మాత్రమే: గోంజో ప్రోగ్రామర్ ప్రేరణ, భయాందోళనల అలలపై ప్రయాణిస్తాడు. డెవలపర్ కూలినప్పుడు కోడ్ పూర్తవుతుంది.

10. సాఫ్ట్‌వేర్ ఊహించలేనిదిగా ఉండాలి: మంచి గోంజో ప్రోగ్రామ్‌లో కొంత యాదృచ్ఛికత ఉంటుంది. ప్రతి బటన్ నొక్కినప్పుడు అదే జరిగితే అది పారిశ్రామిక ఉత్పత్తి, కళ కాదు.

11. బాధ్యత? మినహాయింపు: లైసెన్స్‌లో “ఇది నడిస్తే, అది మీ సమస్య” అనే ఒకే నిబంధన ఉండాలి. డెవలపర్ దేవుడు కాదు; యంత్ర నాశనానికి సాక్షి.

12. నిష్క్రమణ వ్యూహం: ప్రాజెక్ట్ కూలితే వివరణ ఇవ్వవద్దు. Git history తొలగించి, hard drive కాల్చి, mobile signal లేని మెక్సికో ప్రాంతాన్ని వెతకండి.
