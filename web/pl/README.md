1. Programista jest częścią kodu: Nie istnieje obiektywne tworzenie oprogramowania. Oprogramowanie nie jest narzędziem, lecz binarnym odciskiem stanu psychicznego, ciśnienia krwi i gniewu programisty w danym dniu.

2. Chaos jest święty: Jeśli algorytm jest zbyt przejrzysty, to podejrzane. Prawdziwy kod gonzo jest jak dżungla: niebezpieczny, mroczny, a tylko jego twórca wie, gdzie znajdują się pułapki.

3. Testowanie na serwerze produkcyjnym: Testy jednostkowe to sport dla tchórzy i biurokratów. Prawdziwy programista gonzo debugguje bezpośrednio na produkcji, pośród krzyków użytkowników.

4. Dokumentacja jest fikcją: Komentarze do kodu nie są wyjaśnieniami, lecz wewnętrznymi monologami, manifestami politycznymi lub wołaniem o pomoc. Kto nie rozumie kodu, nie jest godny go używać.

5. Wskaźnik (pointer) jest panem: Używaj języka programowania, w którym nikt cię nie ogranicza! Bezpośrednie zarządzanie pamięcią jest gwarancją twojej wolności. Używanie bezpiecznych typów to tylko kajdany. Korzystaj z adresów pamięci, jakby jutra miało nie być. Memory Leak jest twoim krzykiem, którego nikt nie słyszy.

6. Architektura oparta na kofeinie: Jakość kodu jest wprost proporcjonalna do ilości spożytych środków pobudzających i odwrotnie proporcjonalna do liczby godzin przeznaczonych na sen.

7. Komunikat o błędzie jako sztuka: Komunikat o błędzie nie powinien pomagać, lecz szokować. Użytkownik musi przy każdym Runtime Error odczuwać pogardę maszyny i jej twórcy.

8. Nigdy nie sprzątaj (Refactor): To, co raz napisałeś w transie, jest święte. Jeśli dotkniesz tego, aby uczynić to „ładniejszym”, zabijesz duszę oprogramowania.

9. Termin jest tylko sugestią: Programista gonzo nie pracuje według zegara, lecz płynie na falach inspiracji i paniki. Kod jest gotowy, gdy programista się załamuje.

10. Oprogramowanie powinno być nieprzewidywalne: Dobry program gonzo zawsze zawiera odrobinę losowości. Jeśli po każdym naciśnięciu przycisku dzieje się to samo, jest to nudny produkt przemysłowy, a nie sztuka.

11. Odpowiedzialność? Wykluczona: Umowa licencyjna powinna składać się z jednego punktu: „Jeśli się uruchomi, to twój problem.” Programista nie jest Bogiem, tylko świadkiem zagłady maszyny.

12. Strategia wyjścia: Gdy projekt upadnie, nie tłumacz się. Usuń historię Git, spal dysk twardy i znajdź miejsce w Meksyku, gdzie nie ma zasięgu komórkowego.
