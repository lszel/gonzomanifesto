1. De ontwikkelaar maakt deel uit van de code: Objectieve ontwikkeling bestaat niet. Software is geen gereedschap, maar de binaire afdruk van de gemoedstoestand, bloeddruk en woede van de programmeur op die dag.

2. Chaos is heilig: Als een algoritme te overzichtelijk is, is dat verdacht. Echte gonzo-code is als een jungle: gevaarlijk, donker, en alleen de maker weet waar de vallen liggen.

3. Testen op de productieserver: Unit testing is de sport van lafaards en bureaucraten. De echte gonzo-programmeur debugt rechtstreeks in productie, te midden van de kreten van gebruikers.

4. Documentatie is fictie: Commentaar bij de code is geen uitleg, maar een innerlijke monoloog, politiek manifest of noodkreet. Wie de code niet begrijpt, is het gebruik ervan niet waardig.

5. De pointer is de baas: Gebruik een programmeertaal waarin je niet wordt beperkt! Rechtstreeks geheugenbeheer is de garantie van je vrijheid. Het gebruik van veilige typen is slechts een keten. Gebruik geheugenadressen alsof er geen morgen bestaat. De Memory Leak is jouw schreeuw die niemand hoort.

6. Architectuur op basis van cafeïne: De kwaliteit van de code is recht evenredig met de hoeveelheid geconsumeerde stimulerende middelen en omgekeerd evenredig met het aantal uren slaap.

7. Foutmelding als kunst: De foutmelding moet niet helpen, maar choqueren. De gebruiker moet bij elke Runtime Error de minachting van de machine en haar maker voelen.

8. Ruim nooit op (Refactor): Wat je ooit in trance hebt geschreven, is heilig. Als je het aanraakt om het „mooier” te maken, dood je de ziel van de software.

9. De deadline is slechts een suggestie: De gonzo-programmeur werkt niet op de klok, maar rijdt op de golven van inspiratie en paniek. De code is klaar wanneer de ontwikkelaar instort.

10. Software moet onvoorspelbaar zijn: Een goed gonzo-programma bevat altijd een beetje willekeur. Als bij elke druk op een knop hetzelfde gebeurt, is het een saai industrieel product, geen kunst.

11. Verantwoordelijkheid? Uitgesloten: De licentieovereenkomst moet uit één punt bestaan: „Als het start, is het jouw probleem.” De ontwikkelaar is niet God, slechts een getuige van de ondergang van de machine.

12. De exitstrategie: Wanneer het project instort, geef dan geen uitleg. Verwijder de Git-geschiedenis, verbrand de harde schijf en zoek een plek in Mexico zonder mobiel bereik.
